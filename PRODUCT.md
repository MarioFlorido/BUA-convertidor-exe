# Product

## Register

product

## Users

**Primary audience:** Mixed — educators/instructional designers and administrative/support staff at Universidad de Alicante.

**Context:** Users convert their course materials from Word documents into eXeLearning (.elpx) projects, often with variations in technical comfort. Some are subject-matter experts doing one-off conversions; others are content managers handling bulk operations. All value speed and reliability.

**Job to be done:** Transform educational content reliably, locally, and verifiably—without uploading to external services—so course creators can focus on teaching, not format wrangling.

## Product Purpose

ConvertidoreXe transforms Microsoft Word documents into eXeLearning courses, running entirely in the browser without relying on cloud services or external dependencies.

**Why it exists:**
- Educators at UA need a reliable, institution-owned conversion tool without vendor lock-in.
- Word is the de facto standard for course authoring; eXeLearning is the institutional platform.
- Local processing ensures privacy and eliminates the overhead of cloud-based conversion services.

**What success looks like:**
- Users trust ConvertidoreXe as their default converter—it "just works" across varied document structures.
- Conversion feels fast; result quality is predictable and rarely requires rework.
- Users feel in control: they can see the structure, configure it, preview the outcome, and export offline.

## Brand Personality

**Three words:** Minimalist, efficient, technical.

**Voice & tone:**
- **Minimalist:** No ornament, no distraction. Every UI element earns its place by communicating or enabling action.
- **Efficient:** Workflows are direct. Language is precise. Status is transparent.
- **Technical:** Users expect clarity on structure, validation, and process—speak honestly about what's happening.

**Emotional goal:** Calm confidence. Users should feel in control and unsurprised by the outcome.

## Anti-references

- Overly playful or decorative UX (gamified elements, emoji-heavy labels, unnecessary charm).
- Heavy or complex animations that slow down interaction.
- Ambiguity about data handling or process status.
- Treating Word documents as a "dumb format" requiring hand-holding; assume users understand document structure.

## Design Principles

1. **Trust through transparency** — Show the structure. Display status clearly. Process everything locally so the user never worries where their data goes.
2. **Efficiency over embellishment** — Minimal motion. Direct workflows. Clear CTAs. Don't animate for delight; animate only when it clarifies state or guides attention.
3. **Semantic clarity** — Structure configuration is the hardest part; make it unambiguous. Headings, labels, and error messages must be precise.
4. **Institutional identity** — Reflect Universidad de Alicante's visual standards. Professional, official, trustworthy.
5. **Accessible by design** — Works for mixed technical backgrounds. Keyboard navigation must be smooth. Forms must be understandable.

## Accessibility & Inclusion

WCAG 2.1 AA compliance and keyboard navigation are non-negotiable for institutional adoption. Current baseline is solid; maintain it as the minimum floor for any visual changes.

- All interactive elements must be keyboard-accessible.
- Focus indicators must be visible and clear.
- Semantic HTML + ARIA labels for screen reader users.
- Reduced-motion support: animations degrade to instant transitions; no parallax or scroll-driven effects.
- Form validation must be clear and non-destructive.
