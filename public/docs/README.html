ConvertidoreXe — Léeme

Convierte documentos Word a proyectos eXeLearning (.elpx) y a PDF con estilo visual personalizable. Todo el procesamiento sucede en el navegador — ningún archivo sale de tu dispositivo.

¿Qué hace?

ConvertidoreXe v0.2.0 es una aplicación web desarrollada por la Biblioteca Universitaria de la Universidad de Alicante que transforma un documento Word en un recurso interactivo listo para eXeLearning, o en un PDF estructurado con portada, índice automático, encabezados y pies.

  1. Subes un documento Word (.docx).
  2. Configuras la jerarquía: qué nivel ocupa cada H1 y qué hace cada H2.
  3. Eliges un estilo visual.
  4. Descargas el .elpx para abrirlo en eXeLearning.
  5. O exportas directamente a PDF con portada, índice, encabezados y pies.
flowchart LR
    A([Subir DOCX]) --> B[Parsear con Mammoth]
    B --> C[Configurar estructura]
    C --> D[Seleccionar estilo]
    D --> E[Convertir]
    E --> F([Descargar ELPX / PDF])
Privacidad: no hay servidor backend. El documento que subes nunca sale de la pestaña del navegador.

Arquitectura: pipeline de tres capas

El SemanticDocument es el núcleo del sistema: un modelo agnóstico al formato de salida que describe el documento como páginas y bloques semánticos. Los renderers ELPX y PDF son completamente independientes entre sí — añadir un nuevo formato (SCORM, EPUB…) es escribir un renderer adicional sin tocar lo demás. 

flowchart TD
    DOCX([DOCX]) --> Parser[DocxParser / Mammoth.js]
    Parser --> HTML[HTML intermedio]
    HTML --> Struct[parseDocumentStructure]
    HTML --> Builder[SemanticBuilder]
    Struct --> Builder
    Builder --> SemDoc([SemanticDocument])
    SemDoc --> ELPX[ElpxRenderer / .elpx]
    SemDoc --> PDF[PrintHtmlRenderer / PDF]

Modelo SemanticDocument

SemanticDocument
├── title: string
├── subtitle: string
└── pages: SemanticPage[]
        ├── title: string
        ├── level: 1 | 2 | 3 | 4
        ├── parentIndex: number | null
        └── blocks: SemanticBlock[]
                ├── title: string   // '' = bloque sin título iDevice
                └── html: string

Sistema de estilos

Los estilos son plugins ZIP cargados en runtime, sin backend. Dos fuentes convergen en el ThemeRegistry, la fuente de verdad única de la aplicación.

    subgraph Oficiales[Estilos oficiales - todos los usuarios]
        Repo[public/themes/id/ - en git] -->|pack-themes| ZIP[id.zip - generado]
        ZIP -->|fetch al arrancar| BIP[BuiltInThemeProvider]
    end
    subgraph Locales[Estilos locales - solo este navegador]
        Upload[ZIP subido por el usuario] --> IDB[IndexedDB]
        IDB --> UTP[UserThemeProvider]
    end
    BIP --> Reg[ThemeRegistry]
    UTP --> Reg
    Reg --> Sel[Selector de estilos]

Etiquetas semánticas BUA

Dentro del documento Word puedes marcar cajas semánticas con corchetes:

[importante]
Contenido del bloque importante.
[fin]

[ejemplo]
Texto del ejemplo.
[fin]

[definición]
Texto de la definición.
[fin]

Y clases aplicadas a la tabla siguiente:

[horizontal]   →  tabla horizontal estilizada
[vertical]     →  tabla vertical estilizada

La detección es robusta frente a las particularidades de Word:

  • Case-insensitive: [IMPORTANTE], [Importante], [importante]
  • Tildes: [definición] ≡ [definicion]
  • Bookmarks invisibles de Word (<a></a>) dentro de los corchetes — se limpian automáticamente
  • [horizontal] y [vertical] entre dos cajas no rompen la detección de la siguiente
  • Saltos de línea (Shift+Enter) junto a marcadores se normalizan a saltos de párrafo

ElementoDescripción

Detección de idioma del estilo (3 capas)

  1. Etiquetas BUA en CSS: "Exemple" → CA · "Example" → EN · "Ejemplo" → ES
  2. Palabras clave del ID: PhD → EN · Doctorat / Grau → CA
  3. Fallback: es

Instalación y desarrollo

Requisitos

  • Node.js ≥ 18
  • npm ≥ 9

Clonar e instalar

git clone git@github.com:MarioFlorido/BUA-convertidor-exe.git
cd BUA-convertidor-exe
npm install

Servidor de desarrollo

npm run dev

Accede a http://localhost:5173/BUA-convertidor-exe/

Build de producción

npm run build      # TypeScript + Vite → dist/
npm run preview    # Previsualizar el build
npm run deploy     # Build + publicación en gh-pages

Despliegue

Cada push a main lanza una GitHub Action que construye el proyecto y publica el resultado en GitHub Pages. La configuración está en:

  • vite.config.ts → base: '/BUA-convertidor-exe/'
  • .github/workflows/deploy.yml → build + deploy automático
  • Branch gh-pages → contiene el build estático

Problemas habituales

«No se pudo cargar la plantilla base»
Falta public/base.elpx. Restaurar con git checkout public/base.elpx.

«El estilo no aparece en el selector tras subirlo»
La validación falló (ZIP sin style.css o estructura inválida). Revisar consola del navegador.

«El estilo funciona pero sin miniatura»
El ZIP no incluye screenshots.png en la raíz. El estilo funciona igual, pero sin imagen en el selector.

«Las cajas BUA no tienen colores en el PDF»
El style.css del estilo debe declarar .bua_ejemplo, .bua_definicion, .bua_importante con border-left y ::before { content: "Etiqueta" }.

«El PDF no muestra encabezados/pies»
Paged.js requiere conectividad para cargar desde CDN (unpkg.com). Para entornos offline, descargar Paged.js localmente y actualizar la URL en semanticDocumentToPrintHtml.ts.

«La interfaz dice [ES] pero el estilo es en inglés o catalán»
Falta la etiqueta <language> en el config.xml del estilo. Añadir <language>en</language> o <language>ca</language> y republicar.

Inspiración y agradecimientos

Este proyecto se inspira en el trabajo de Juanjo de Haro sobre HACKeXe, una herramienta pionera para la edición avanzada de proyectos eXeLearning. Su enfoque sobre la manipulación directa del formato ELPX fue la semilla conceptual de este convertidor.

ConvertidoreXe extiende esa idea hacia un flujo editorial completo: parte de un documento Word con estructura semántica y produce un recurso listo para eXeLearning o un PDF académico, sin necesidad de intervención manual en el XML.

Consulta docs/COMPARISON.md para una comparación detallada entre HACKeXe y ConvertidoreXe.
