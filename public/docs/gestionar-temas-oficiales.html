Gestionar estilos oficiales

Publica, actualiza y elimina los estilos que ven todos los usuarios, desde el propio Convertidor — sin Terminal ni scripts.

Antes de empezar: necesitas un token de acceso de GitHub (fine-grained PAT) limitado a este repositorio, con permiso Contents: Read and write. Se crea una sola vez y se reutiliza. Usa Chrome o Edge (la selección de carpeta no funciona en Firefox/Safari).

Flujo general

flowchart TD
    Start([Panel de administración]) --> Auth[Introducir token de GitHub]
    Auth --> Pick[Seleccionar carpeta del tema]
    Pick --> Val[Validar + previsualizar]
    Val --> Pub[Publicar / Actualizar / Eliminar]
    Pub --> Commit[Commit a main vía API de GitHub]
    Commit --> CI([CI deploy.yml reconstruye y despliega])
    CI --> GH([Visible para todos en 1-2 min])

Dónde está el panel

  1. Abre el Convertidor y pulsa «Estilos eXeLearning» (arriba a la derecha).
  2. Baja hasta la sección «Administración de temas oficiales».
  3. Pega tu token y pulsa Entrar. Si quieres no repetirlo, elige «Recordar… en este dispositivo».
Crear el token de GitHub (una sola vez)
  1. En GitHub: Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
  2. Resource owner: id_propietario_repo Expiration: larga (p. ej. 1 año).
  3. Repository access: Only select repositories → BUA-convertidor-exe.
  4. Repository permissions → Contents: Read and write. (GitHub añade Metadata: Read-only solo, es normal.)
  5. Generate token y copia el valor (github_pat_…). Se muestra una sola vez.
El mismo token vale en los tres entornos (localhost de casa, producción en github.io, localhost del trabajo): es una credencial de GitHub, no del sitio. Cada navegador/equipo lo recuerda por separado.
Publicar o actualizar un estilo oficial
  1. En el panel, pulsa «Seleccionar carpeta…» y elige la carpeta del tema (p. ej. Doctorado_26-27).
  2. Revisa la validación (errores en rojo bloquean; avisos en amarillo no) y la previsualización (nombre, actividad y descripción son editables).
  3. Pulsa «Publicar tema oficial». Si el id ya existe, el botón pasa a «Actualizar»: se reemplazan los archivos y se borran los que ya no estén en la carpeta.
  4. Listo: se hace un único commit en main y el CI reconstruye y despliega en 1-2 minutos.
Importante: la carpeta debe contener al menos config.xml y style.css. El nombre de la carpeta es el ID del estilo (Doctorado_26-27 → ID Doctorado_26-27). La basura de macOS (__MACOSX, .DS_Store) se descarta automáticamente.
Eliminar un estilo oficial
  1. En la lista «Temas oficiales existentes», pulsa Eliminar en el que quieras.
  2. Para confirmar, escribe el id exacto del tema (doble confirmación de seguridad).
  3. Pulsa «Eliminar def.»: se borra la carpeta y se actualiza el catálogo en un commit. Recuperable desde el historial de git si hiciera falta.
Opciones avanzadas (probar sin riesgo)

Dentro del panel, en «Opciones avanzadas»:

  • Rama destino: cámbiala a admin-themes-test para ensayar sin tocar producción.
  • Simular (dry-run): calcula qué se subiría/borraría sin modificar nada.
Para publicar de verdad, deja la rama en main y el dry-run desactivado.
